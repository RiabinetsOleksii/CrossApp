**Семестровий проєкт:** Наскрізна розробка системи моніторингу IoT-пристроїв (тижні 1–16).

---

## 1. Предметна область (Domain)

* **Назва:** Система моніторингу IoT-пристроїв.
* **Призначення:** Централізований збір, парсинг та обробка даних телеметрії з мікроконтролерів та підключених до них датчиків.
* **Ключові сутності:**
  * `Controller` — мікроконтролер (наприклад, ESP32) з налаштуваннями мережі та протоколу обміну даними (MQTT, HTTP).
  * `Sensor` — апаратний датчик (наприклад, HC-SR04, TM1637), прив'язаний до певної локації.
  * `Telemetry` — пакет даних із показниками, отриманий від конкретного сенсора в заданий момент часу.

---

## 2. Архітектура та структура рішення (Solution)

Проєкт організовано за принципом відокремлення консольного інтерфейсу від основної логіки:

```text
CrossApp/
├── CrossApp.slnx
├── README.md
├── .gitignore
├── data/
│   └── sample.csv
└── src/
    ├── Core/
    │   ├── Core.csproj
    │   ├── EnvironmentInfo.cs
    │   ├── Dto/
    │   │   ├── DeviceDomainDto.cs
    │   │   └── ImportResult.cs
    │   └── Import/
    │       └── DeviceCsvImporter.cs
    └── Cli/
        ├── Cli.csproj
        └── Program.cs
```

### Призначення компонентів

* **`src/Core` (Class Library):**
  * містить DTO-моделі (ієрархію `DeviceDomainDto`) та логіку відмовостійкого імпорту;
  * містить інформацію про середовище виконання;
  * компілюється у `.dll`;
  * не залежить від `Cli`.
* **`src/Cli` (Console Application):**
  * обробляє аргументи командного рядка та шляхи до файлів;
  * викликає імпортер із `Core`;
  * відповідає за форматований вивід записів та помилок у консоль.
* **Правило залежностей:** `Cli` → `Core`.

## 3. Інструкція зі збірки та запуску

### Збірка всієї системи

Перед запуском необхідно зібрати проєкт:
```bash
dotnet build
```

### Запуск програми (Обхід Application Control)

Оскільки локальна політика безпеки Windows (Smart App Control / Defender) може блокувати запуск нових непідписаних `.exe` файлів, програму налаштовано на безпечний запуск напряму через скомпільовану бібліотеку для **.NET 8.0**.

**Основний запуск (файл за замовчуванням `data/sample.csv`):**
```bash
dotnet src/Cli/bin/Debug/net8.0/Cli.dll
```

**Запуск із вказанням конкретного файлу:**
```bash
dotnet src/Cli/bin/Debug/net8.0/Cli.dll data/sample.csv
```

## 4. Формати даних та імпорт

* **Кодування:** UTF-8.
* **Роздільник CSV:** `;`.
* **Основний формат:**

```text
Type;Id;Col1;Col2;Col3
```

Залежно від префікса `Type` рядок розпізнається як різна сутність:
* `C` (Контролер): `C;Id;IpAddress;Protocol` *(Приклад: `C;C-001;192.168.1.10;MQTT`)*
* `S` (Сенсор): `S;Id;Model;Location` *(Приклад: `S;S-001;HC-SR04;Зона збірки`)*
* `T` (Телеметрія): `T;Id;SensorId;Value;Timestamp` *(Приклад: `T;T-001;S-001;15.5;2026-10-04T10:00:00`)*

**Особливості імпортера:**
* Для представлення даних використовуються незмінні `record`-типи (`ControllerDto`, `SensorDto`, `TelemetryDto`), успадковані від базового `DeviceDomainDto`.
* Розбір CSV реалізовано через `switch expression` і `pattern matching` (зокрема `list patterns`, охоронні умови `when` та `TryParse` з `CultureInfo.InvariantCulture`).
* Процес є відмовостійким: пошкоджений рядок не припиняє імпорт. Помилка додається до колекції `Errors` із вказівкою номера рядка, а валідні дані продовжують завантажуватися.

## 5. Дослідження режимів публікації (.NET Publish)

Під час виконання лабораторних робіт досліджено способи публікації застосунку для `win-x64`:

| Режим публікації | Розмір каталогу | Потрібен .NET Runtime |
| :--- | ---: | :---: |
| **Framework-dependent** | ≈ 200 КБ | Так |
| **Self-contained** | ≈ 76 МБ | Ні |
| **Single-File** | ≈ 70 МБ | Ні |
| **Trimmed Single-File** | ≈ 12 МБ | Ні |

*Приклади команд публікації:*
```bash
# Framework-dependent
dotnet publish src/Cli -c Release -r win-x64 --self-contained false

# Self-contained
dotnet publish src/Cli -c Release -r win-x64 --self-contained true
```

## 6. Multi-targeting та умовна компіляція

Бібліотеку `src/Core` та застосунок `src/Cli` налаштовано на збірку під дві версії платформи:

```xml
<TargetFrameworks>net8.0;net10.0</TargetFrameworks>
```

Після виконання `dotnet build` формуються окремі збірки для кожної версії (`net8.0` та `net10.0`). У коді використовується умовна компіляція (директиви препроцесора `#if NET10_0_OR_GREATER`), що дозволяє враховувати специфічні API новіших платформ без дублювання кодової бази проєкту.
