## 1. Предметна область (Domain)

* **Назва:** Система моніторингу IoT-пристроїв.
* **Призначення:** Централізований збір, парсинг та обробка даних телеметрії з мікроконтролерів та підключених до них датчиків.
* **Ключові сутності:**
  * `Controller` — мікроконтролер (наприклад, ESP32) з налаштуваннями мережі та протоколу обміну даними (MQTT, HTTP).
  * `Sensor` — апаратний датчик (наприклад, HC-SR04, TM1637), прив'язаний до певної локації.
  * `Telemetry` — пакет даних із показниками, отриманий від конкретного сенсора в заданий момент часу.

---

4. Формати даних та імпортКодування: UTF-8.Роздільник CSV: ;.Основний формат:PlaintextType;Id;Col1;Col2;Col3
Залежно від префікса Type рядок розпізнається як різна сутність:C (Контролер): C;Id;IpAddress;Protocol (Приклад: C;C-001;192.168.1.10;MQTT)S (Сенсор): S;Id;Model;Location (Приклад: S;S-001;HC-SR04;Зона збірки)T (Телеметрія): T;Id;SensorId;Value;Timestamp (Приклад: T;T-001;S-001;15.5;2026-10-04T10:00:00)Особливості імпортера:Для представлення даних використовуються незмінні record-типи (ControllerDto, SensorDto, TelemetryDto), успадковані від базового DeviceDomainDto.Розбір CSV реалізовано через switch expression і pattern matching (зокрема list patterns, охоронні умови when та TryParse з CultureInfo.InvariantCulture).Процес є відмовостійким: пошкоджений рядок не припиняє імпорт. 6. Multi-targeting та умовна компіляціяБібліотеку src/Core та застосунок src/Cli налаштовано на збірку під дві версії платформи:XML<TargetFrameworks>net8.0;net10.0</TargetFrameworks>
Після виконання dotnet build формуються окремі збірки для кожної версії (net8.0 та net10.0). У коді використовується умовна компіляція (директиви препроцесора #if NET10_0_OR_GREATER), що дозволяє враховувати специфічні API новіших платформ без дублювання кодової бази проєкту.
