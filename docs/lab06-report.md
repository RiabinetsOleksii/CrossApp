# Звіт до лабораторної роботи №6

**Тема:** Доменні події, делегати Action/Func, лямбда-вирази.

**Мета:** Реалізувати повідомлення зовнішніх компонентів про успішні зміни стану сенсорів без залежності доменної логіки від способу відображення або збереження повідомлень.

## 1. Доменні події

У системі CrossApp подіями є успішне додавання сенсора (`Added`), монтаж і активація (`Mounted`), передача на обслуговування (`Maintenance`), позначення несправності (`Broken`) та видалення (`Removed`). Подія містить ID, вид зміни, статус до і після, локацію та час.

## 2. Подія в сервісі

У `SensorService` оголошено `event EventHandler<SensorChangedEventArgs>? Changed;`. Метод `OnChanged` створює аргументи та викликає `Changed?.Invoke(this, change)` тільки після успішної зміни стану та оновлення сховища. Якщо операція завершилась винятком, повідомлення не виникає.

## 5. Додаткові завдання

**Додаткове №1:** `INotificationSink` оголошений у Core, а `ConsoleSink` і `FileSink` реалізовані в Cli. `CompositeNotificationSink` передається до `SensorService` через конструктор за допомогою ручного DI (`--sinks`). Порівняння: подія дозволяє підписувати й відписувати багато зовнішніх обробників, а sink є явно переданою сервісу абстракцією для сповіщень. На відміну від події, sink у прикладі залишається активним після `-=` обробника події.

**Додаткове №2:** `SensorImportReporter.ImportLines` приймає `Action<string>` і викликає його для пропущених рядків. У демонстрації імпортовано 2 сенсори та пропущено 2 некоректні рядки. Сам Core не вирішує, куди виводити повідомлення.

## 6. Порівняння події з прямим викликом логера

Якби `SensorService` безпосередньо викликав логер, Core залежав би від конкретного способу виведення, а для нового підписника довелося б змінювати сервіс. Подія дозволяє додавати обробники в Cli без змін Core та тестувати появу повідомлень у пам'яті.

## Висновок

У лабораторній роботі реалізовано доменні події, два підписники, лямбда-вираз із замиканням, відписку, журналювання та перевірку відсутності події під час помилки. Використано `Func<Sensor,bool>` для пошуку. Виконано додаткові завдання: абстракція `INotificationSink` із консольним і файловим обробниками та `Action<string>` для звітності під час імпорту. Доменно-сервісний шар не містить прямого виведення повідомлень.
