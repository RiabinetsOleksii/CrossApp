# Звіт до лабораторної роботи №7

**Тема:** Звіти через LINQ: фільтри, проєкції, групування, топ-N, агрегати.

**Мета:** реалізувати LINQ to Objects у Core для аналітики IoT-сенсорів, показати
результати в Cli, дослідити відкладене виконання та виконати чотири додаткові завдання.

## 1. Перелік основних запитів

| Метод | Питання | Оператори |
| --- | --- | --- |
| `LowInterval` | Які сенсори мають інтервал нижче порога? | Where, OrderBy, ThenBy, Select, ToList |
| `TopByInterval` | Які сенсори мають найбільші інтервали? | TopBy (OrderByDescending, ThenBy, Take), Select |
| `ByModel` | Які моделі сенсорів і сумарні інтервали? | GroupBy, Select, Count, Sum, OrderByDescending |
| `Totals` | Які кількість, сума, середній і максимальний інтервали? | ToList, Sum, Average, Max |

У роботі використано `PingIntervalMs` замість `Quantity` зі зразка методички,
а `Model` — як категорію. Запити повертають record-DTO, а не об'єкти `Sensor`.

## 2. Фрагмент GroupBy із проєкцією

```csharp
return source.GroupBy(sensor => sensor.Model, StringComparer.OrdinalIgnoreCase)
    .Select(group => new SensorGroupSummary(
        group.Key, group.Count(), group.Sum(s => s.PingIntervalMs)))
    .OrderByDescending(summary => summary.TotalPingIntervalMs)
    .ThenBy(summary => summary.Key, StringComparer.Ordinal)
    .ToList();
```

`group.Key` — назва моделі; `group.Count()` — кількість сенсорів;
`group.Sum(...)` — сума їхніх інтервалів опитування.

## 4. Відкладене виконання

Запит `source.Where(...)` лише описує умову; перевірка виконується, коли викликають
`Count()`. Якщо додати сенсор до списку перед другим Count(), кількість зростає
на один. `ToList()` створює окремий список із поточним результатом, тому після
очищення вихідного списку знімок залишається незмінним.

**Очікувані числа зі стандартними SampleData:** до змін **3**, після змін **4**,
у знімку після очищення **4**. Перевірити реальним запуском.

## 5. Додаткові завдання

1. `GroupJoin` — з'єднання колекції сенсорів із демонстраційними вимірюваннями,
   включно із сенсорами без відповідних записів.
2. `TopBy<T>` — власний метод-розширення, використаний у двох звітах.
3. Синтаксис `from ... group ... into ... select` — другий запис `ByModel`;
   методний синтаксис зручніший для послідовної обробки, query syntax — для групування.
4. `Stopwatch` — порівняння на 100 000 згенерованих сенсорів.
   Без проміжного `ToList`: ___ мс; з проміжним `ToList`: ___ мс.
   Проміжний список створює додаткові виділення пам'яті; час залежить від ПК.
